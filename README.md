# Quantum-enhanced pneumonia classification on PneumoniaMNIST

A hybrid quantum-classical image classifier for paediatric chest X-rays (normal vs pneumonia), simulated
locally with [PennyLane](https://pennylane.ai) and PyTorch, and compared honestly against a classical
control of identical size.

```
28x28 X-ray -> small CNN -> 8 features -> 8-qubit variational circuit -> linear -> P(pneumonia)
                                       \-> classical control: Linear(8, 8) + tanh (72 weights)
```

The two models share everything except that 8 -> 8 middle block, so any difference in their results is
caused by the quantum circuit. A validation-only sweep chose a 1-layer circuit (24 angles); the default
3-layer circuit (72 angles, exactly the control's size) is reported as a secondary, parameter-matched
comparison. Everything runs on a laptop CPU; no quantum hardware or cloud is used.

**Answer in one line:** the hybrid clears the published ResNet-18 baseline comfortably, but so does the
classical control; the quantum layer matched it within noise and never beat it on mean AUC or accuracy (details in
[REPORT.md](REPORT.md), Section 6).

## Desktop app

**Double-click `QuantumPneumoniaLab.exe`** in the project folder (after installing, below). It opens a window
that drives this project's own code:

| Tab | What you can do |
|---|---|
| Overview | Where the project stands, the headline table and the hybrid-vs-classical verdict, quick actions |
| Data | Download, verify (MD5 and class counts) or delete PneumoniaMNIST at 28/64/128/224 px; browse images and their augmentations; add or remove folders of your own X-rays |
| Train | Configure and start a training run (every setting, CPU or GPU) or a whole stage of runs; live loss/AUC curves, progress, elapsed time and time left; stop at any time |
| Runs | Every run with its status, validation and test scores, learning curves, gradient norms and full configuration; delete runs |
| Results | All generated tables and figures; rebuild them (or the slow noise study) with one click |
| Predict | Classify an X-ray (or a random validation image) and see every step inside the model: CNN features, rotation angles, the circuit's outputs, the head's contributions, the probability; batch-predict a folder and save a CSV |
| Learn | Sliders for one qubit (Bloch vector and the exact formula), what the CNOT ring does, the circuit diagrams and the beginner guide |
| System | Versions, CPU/GPU, disk use, run the test suite, CPU-vs-GPU benchmark |
| Jobs | Every job started in the session: status, progress, time left, full output, stop |

The .exe is a small launcher: it starts `app\main.py` with the project's `.venv`, so it must stay in the project
folder. To run without it: `.venv\Scripts\pythonw.exe app\main.py`. To rebuild it:
`.venv\Scripts\python.exe -m pip install pyinstaller`, then `.venv\Scripts\python.exe app\build_exe.py`.

## Install (Windows, Python 3.11-3.13)

```bash
py -3.13 -m venv .venv
```

```bash
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`requirements.txt` pins the exact versions used (CPU-only PyTorch from PyTorch's own index). Calling the venv's
`python.exe` directly avoids PowerShell's script-execution policy blocking `Activate.ps1`. On Linux/macOS use
`python3 -m venv .venv` and `.venv/bin/python` instead.

## Use

All commands run from the project folder. The dataset (about 4 MB) downloads into `data/` on first use.

```bash
.venv\Scripts\python.exe -m pytest
```

```bash
.venv\Scripts\python.exe src\train.py --mode hybrid --seed 0
```

```bash
.venv\Scripts\python.exe src\evaluate.py
```

```bash
.venv\Scripts\python.exe src\predict.py --input path\to\xray.png
```

- `train.py` trains one model for one seed into `runs/<name>/seed<k>/`. The defaults are the brief's 8-qubit,
  3-layer hybrid; add `--n_layers 1` for the final 1-layer hybrid, or use `--mode classical` for the control.
  Every hyperparameter is a flag (see `src/config.py`). It never touches the test set. The run folders in
  this repository already hold finished results, so a run whose `metrics.json` exists is skipped; add
  `--force` to retrain it.
- `evaluate.py` is the only script that reads the test set. It scores every finished final model (reusing
  cached test predictions; model weights are not stored in git), writes `runs/summary.csv` and
  `runs/results.md`, refreshes the tables in README.md, REPORT.md and EXPLAINED.md, and draws the figures.
  `--noise` reruns the slow finite-shot and noisy-circuit evaluation.
- `predict.py` accepts a PNG/JPG or a `.npy` array and prints P(pneumonia) and the label. By default it
  averages all trained seeds of the final hybrid (`runs/hybrid_q8_l1`); `--run runs/hybrid_q8_l1/seed0` uses
  one checkpoint. It needs trained weights (`best.pt`) on this machine.

To reproduce everything (sweep, final runs, extensions; several hours on a laptop CPU):

```bash
.venv\Scripts\python.exe src\sweep.py --stage sweep
```

```bash
.venv\Scripts\python.exe src\sweep.py --stage final matched quanv s64 phase7
```

```bash
.venv\Scripts\python.exe src\evaluate.py --noise
```

Stages: `final` = final hybrid, classical control and no-entanglement ablation; `matched` = the 72-parameter
3-layer hybrid; `quanv` and `s64` = the extensions; `phase7` = the post-hoc 60-epoch + weight-averaging recipe.
`--workers N` sets how many runs share the CPU (default 8),
finished runs are skipped, and an interrupted sweep resumes where it stopped. To start from scratch, delete
`runs/` first.

## Project layout

```
src/config.py     all hyperparameters (dataclass + command-line flags); the frozen final configuration
src/data.py       dataset download, class-count checks, transforms, loaders, data figures
src/quantum.py    the variational circuit and its PyTorch wrapper (plus noisy/shot-based variants)
src/models.py     CNN backbone, hybrid/classical model, quanvolution model
src/engine.py     training epoch, prediction, metrics, bootstrap confidence intervals
src/train.py      one run = one configuration + one seed
src/sweep.py      many runs, in parallel, resumable
src/evaluate.py   test-set scoring, tables, figures, noise study, Phase 7 (only reader of the test set)
src/figures.py    plotting functions
src/benchmark.py  CPU-vs-GPU epoch timing
app/main.py       the desktop app (window, Overview and Jobs tabs); app/tab_*.py: one file per tab
app/jobs.py       runs the project's scripts in the background, live progress and time left
app/launcher.py   source of QuantumPneumoniaLab.exe; app/build_exe.py builds it
src/predict.py    single-image inference
tests/            smoke tests (pytest)
runs/             per-run config, history, checkpoint, predictions, metrics; summary tables
figures/          all figures
```

## Data and citation

PneumoniaMNIST is part of MedMNIST v2 (CC BY 4.0), derived from 5,856 paediatric chest X-rays
(Kermany et al.). Cite: J. Yang et al., "MedMNIST v2 - A large-scale lightweight benchmark for 2D and 3D
biomedical image classification", *Scientific Data* 10, 41 (2023), doi:10.1038/s41597-022-01721-8; and
V. Bergholm et al., "PennyLane: Automatic differentiation of hybrid quantum-classical computations",
arXiv:1811.04968.
